# التصدير المحاسبي (Excel) — menuPilot

> ⚠️ **التوافق مع الأصيل الذهبي غير متحقق منه بعد.** لا يوجد في المشروع قالب استيراد رسمي أو مواصفات من الأصيل الذهبي، ولذلك يوفر النظام **طبقة ربط أعمدة قابلة للتعديل** وملف تعريف (`alaseel`) بأسماء أعمدة مؤقتة. لا يُعتبر الملف متوافقًا رسميًا قبل مطابقته مع قالب الاستيراد الفعلي في نسختك من البرنامج (راجع القسم 8).

## 1. التقارير المتاحة

| النوع | Endpoint | المحتوى |
|---|---|---|
| تفاصيل الفواتير (E) | `GET /api/reports/export/invoices` | سطر لكل صنف في كل فاتورة، مع بيانات الفاتورة |
| الفواتير (A) | `GET /api/reports/export/sales` | سطر لكل فاتورة: المجموع، الحسم، الضريبة، الإجمالي، المدفوع، المتبقي |
| المدفوعات (B) | `GET /api/reports/export/payments` | كل دفعة: الطريقة، المبلغ، الحالة، الكاشير، المرجع، رمز الحساب |
| مبيعات الأصناف (C) | `GET /api/reports/export/products` | الكمية المباعة، الإجمالي، الحسم، الضريبة، الصافي لكل صنف |
| المبيعات اليومية (D) | `GET /api/reports/export/daily` | لكل يوم: الطلبات، الفواتير، المبيعات، النقدي، الإلكتروني، المعلّق، الملغى |

الاستجابة ملف `.xlsx` حقيقي بنوع المحتوى `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`، مع الترويسة `X-Export-Rows` (عدد السطور). الواجهة: **المحاسبة والتصدير** (`/owner/accounting`).

## 2. الفلاتر (Query parameters)

| المعامل | القيم |
|---|---|
| `range` | `today`، `yesterday`، `this_week`، `this_month` (الافتراضي)، `previous_month`، `custom` |
| `from`, `to` | `YYYY-MM-DD`، مع `range=custom` أو بدونه |
| `payment_method` | `cash`، `bank`، `wallet`، `electronic`، `ussd` |
| `payment_status` | `paid`، `pending`، `pending_reconciliation`، `rejected` (و`partial`/`unpaid` للفواتير) |
| `invoice_status` | `paid` (الافتراضي: الفواتير المغلقة)، `pending`، `cancelled`، `all` |
| `order_status` | `served`، `ready`، `preparing`، `cancelled`… |
| `cashier_id`، `category` أو `category_id`، `product_id` | تُطبَّق ضمن المطعم فقط |
| `profile` | `generic` أو `alaseel` (يتجاوز إعداد المطعم لهذا التصدير) |
| `format` | `xlsx` فقط |

**غير مدعوم بعد:**
- `branch_id`: النظام بفرع واحد لكل مطعم، ويُكتب «الفرع الرئيسي».
- `waiter_id`: النادل غير مسجّل على الطلب، فعمود «النادل» فارغ. المعاملان مقبولان ولا يغيّران النتيجة.

## 3. الصلاحيات (مطبّقة في الـ Backend)

| الصلاحية | تفتح |
|---|---|
| `export_invoices` | invoices، sales |
| `export_payments` | payments |
| `export_sales` | sales، products، daily |
| `export_reports` | كل التقارير |
| `manage_accounting_settings` | تعديل إعدادات المحاسبة |

- **المالك:** كل الصلاحيات.
- **الكاشير والمدير:** لا صلاحيات تصدير إلا إذا منحها المالك من «الفريق والصلاحيات».
- **النادل والمطبخ:** لا صلاحيات تصدير افتراضيًا.
- **الزبون:** لا يصل أبدًا.
- **أدمن المنصة:** لا يصل إلى بيانات المطاعم، فتصدير على مستوى المنصة غير منفّذ.

كل استعلام مقيَّد بمطعم المستخدم المسجّل (`restaurant_tables.user_id`)، ولا يُقبل أي معرّف مطعم من الطلب.

## 4. قواعد البيانات المالية

- **الفاتورة النهائية** هي جلسة طاولة مغلقة، ولها رقم فاتورة.
- **رقم الفاتورة** (`dining_sessions.invoice_number`):
  - تسلسلي لكل مطعم، ويُصدر عند إغلاق الجلسة، ولا يتغير بعدها.
  - آمن عند التزامن، بقفل صف المطعم مع قيد فريد `(restaurant_id, invoice_number)`.
  - يُعرض بالشكل `{prefix}000123`، والبادئة قابلة للتعديل.
  - الجلسات المغلقة قبل هذه الميزة رُقّمت بترتيب إغلاقها.
- **المبيعات** = الأصناف الفعّالة من الطلبات غير الملغاة. الأصناف الملغاة لا تُحسب مبيعات، وتظهر فقط عند `order_status=cancelled` وفي عمود «ملغى» في التقرير اليومي.
- **المدفوع** = الدفعات المؤكدة (`PAID`) فقط. الحالات الأخرى تظهر كما هي: `PENDING` و`PENDING_RECONCILIATION` و`REJECTED`.
- **حالة الفاتورة:** `PAID`، `PENDING` (جلسة مفتوحة)، `CLOSED_UNPAID` (أُغلقت بمبلغ متبقٍ بسبب)، `CANCELLED`.
- **الحسم** = الفرق بين السعر الأصلي قبل تعديل الكاشير والسعر النهائي.
- **الضريبة** تُحسب من `tax_rate`:
  - إذا كانت الأسعار شاملة الضريبة: `tax = net × r / (1 + r)`.
  - وإلا: `tax = net × r`.

## 5. بنية ملف Excel

- ورقة واحدة باسم عربي، باتجاه من اليمين لليسار.
- **رأس ثابت** (Freeze) مع **فلاتر** على الأعمدة، وعرض الأعمدة يتبع المحتوى.
- **أنواع خلايا حقيقية:**
  - الأرقام والمبالغ خلايا رقمية، والمبالغ بتنسيق `#,##0.00 "₪"` (أو رمز العملة المختارة).
  - التاريخ `yyyy-mm-dd`، والوقت `hh:mm`.
  - النص UTF-8.
- سطر **«الإجمالي»** في آخر الملف للأعمدة القابلة للجمع.
- **ملف فارغ صالح** عند عدم وجود بيانات: الرأس موجود، والإجمالي غير موجود.
- **البث:** السطور تُكتب إلى ملف مؤقت على دفعات (`accounting.chunk`، الافتراضي 1000)، والأرقام الإجمالية تُجلب دفعة واحدة لكل مجموعة (بدون N+1).

المولّد: `app/Support/Export/XlsxWriter.php`، وهو كاتب OOXML بدون مكتبات إضافية ويعتمد على امتداد `zip` الموجود في الـ Dockerfile. تحقّقنا من الملفات بقارئ مستقل (openpyxl): الأنواع، والتنسيقات، والتثبيت، والفلاتر، والنص العربي.

## 6. إعدادات المحاسبة (لكل مطعم)

`GET/PUT /api/accounting/settings`:

```json
{
  "profile": "generic | alaseel",
  "currency": "ILS",
  "invoice_prefix": "INV-",
  "tax_rate": 0,
  "prices_include_tax": true,
  "accounts": { "sales": "…", "cash": "…", "bank": "…", "electronic": "…", "tax": "…", "discount": "…", "customer": "…" },
  "category_accounts": { "مشروبات": "…" },
  "column_mapping": { "invoices": { "product_code": "كود المادة", "waiter": false } }
}
```

- لا توجد أرقام حسابات افتراضية؛ كل مطعم يُدخل أرقامه.
- **عمود «رمز الحساب»:**
  - في سطور البيع: حساب التصنيف إن وُجد، وإلا حساب المبيعات.
  - في المدفوعات: حساب الصندوق أو البنك أو الإلكتروني حسب طريقة الدفع.
- **`column_mapping`:** يعيد تسمية أي عمود (نص حتى 64 حرفًا) أو يحذفه (`false`)، لأي تقرير. الحقول المسموحة معرّفة في `config/accounting.php` → `fields`.

## 7. البنية: الحقل الداخلي ← الحقل المحاسبي ← عمود Excel

```
AccountingExporter (البيانات، حقول داخلية)
      ↓
ExportProfile::columns(export, profile, restaurant mapping)
      ↓
XlsxWriter (خلايا مكتوبة بأنواعها)
```

**لإضافة برنامج محاسبة آخر:**
1. أضف ملف تعريف في `config/accounting.php` → `profiles` (مع `label` و`verified` و`headers`).
2. غيّر ترتيب الأعمدة إن لزم عبر `exports`، أو عبر `column_mapping` للمطعم.

لا تغيير في منطق الفواتير والتقارير.

## 8. المطلوب من الأصيل الذهبي لتفعيل توافق دقيق

1. **ملف Excel نموذجي** يقبله شاشة «استيراد الفواتير / المبيعات» في نسختك، مع رقم الإصدار.
2. **أسماء الأعمدة بالضبط وترتيبها**، وأيها إلزامي.
3. **صيغة التاريخ:** هل هي خلية تاريخ أم نص بصيغة معينة (مثل `dd/mm/yyyy`)؟
4. **الفواصل العشرية والعملة:** هل يُقبل رمز العملة أم يلزم رقم فقط؟
5. **البنية:** هل الاستيراد سطر لكل صنف أم لكل فاتورة؟ وهل للحركات النقدية ملف منفصل؟
6. **الترميزات:**
   - ترميز المواد (رقم المادة) وكيف تُطابق أصناف menuPilot. يمكن إدخال رمز لكل صنف في `menu_items.sku`.
   - ترميز الحسابات (دليل الحسابات) ورموز الصندوق والبنك والمبيعات والضريبة.
   - رموز مراكز الكلفة أو المستودع إن كانت مطلوبة.
7. **معاملة الضريبة والحسم:** هل الضريبة على السطر أم على الفاتورة؟ وهل الحسم قيمة أم نسبة؟
8. **الزبون:** هل الزبون النقدي حساب ثابت، أم يلزم رقم زبون لكل فاتورة؟

بعد الحصول على القالب: عدّل `profiles.alaseel.headers` (وترتيب `exports` إن لزم) واجعل `verified` قيمته `true`، ثم اختبر استيراد ملف حقيقي في الأصيل الذهبي.

## 9. سجل التدقيق

- **كل تصدير** يُسجَّل (`accounting.export`) مع: المستخدم، والمطعم، ونوع التقرير، والفلاتر، والفترة، وعدد السطور، والصيغة، وملف التعريف.
- **تعديل الإعدادات** يُسجَّل (`accounting.settings_updated`) مع القيم قبل التعديل وبعده.
- لا تُسجَّل أي بيانات دفع حساسة.

## 10. قيود معروفة

- القيود الخاصة بالفرع والنادل موضحة في القسم 2.
- **الاستردادات:** لا توجد حركة استرداد مستقلة في النظام. الإلغاءات تظهر في «ملغى / مسترد»، والدفعات المرفوضة تظهر بالحالة `REJECTED`.
- **الترتيب داخل الملف** حسب رقم الجلسة (المعرّف الداخلي)، لا حسب رقم الفاتورة. استخدم فلتر Excel للفرز.
- **حد التصدير:** 20 عملية تصدير في الدقيقة لكل مستخدم.
