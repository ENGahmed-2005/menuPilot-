# UI/UX — menuPilot Mobile

## الاتجاه البصري

عربي أولًا، RTL، هوية دافئة وواضحة: navy `#1F2D3D`، copper `#B8793E`، paper `#FAF7F0`، green `#24664D`، danger `#A33D35`. الأرقام المالية وأرقام الطلبات باتجاه LTR داخل السياق العربي. الخط Tajawal عند تضمينه في المنتج مع مراعاة رخصته، وfallback system. النص العادي ≥16؛ الصغير12–14 للبيانات الثانوية، ولا يُعتمد على اللون وحده للحالة.

Spacing8/12/16/24/32؛ radius12 controls و20cards؛ هدف لمس48 على الأقل، margins16 للهاتف؛ CTA ثابت فوق SafeArea؛ bottom sheet له عنوان وزر إغلاق ووصول قارئ شاشة. لا أفقي scroll عند360px. اختبر 200% font scaling. استخدم نصًا ورمزًا مع حالات الاتصال والدفع.

`prototype.html` يعرض شاشات تفاعلية بأسماء مطاعم وطلبات توضيحية، مع قائمة شاشة وحالة للعرض. لا API حقيقية فيه. الـprototype يشرح السلوك ولا يمثل كل تفاصيل المنطق الإنتاجي؛ العقد ومعايير القبول أدناه تحكم التنفيذ.

## رحلة الزبون

الدليل → المنيو → تفاصيل صنف → السلة → checkout → تأكيد نجاح بـ201 → التتبع. يظل زر الشراء معطّلًا للنوع غير المتاح. عند تغيير المطعم تظهر رسالة للاحتفاظ بالسلة الحالية أو تفريغها. عند تغيّر السعر/نفاد صنف تُحدّث البيانات وتعرض الفروقات قبل إعادة الإرسال. الدفع cash هو الاختيار الأول؛ transfer يظهر شرحًا ورفع إثبات فقط إذا قرر الفريق تضمينه في MVP.

لا يُعرض مخطط السيارة على خريطة كأن تتبع السائق متاح. التتبع الحالي مراحل + ETA تقديري؛ لا وعد بوقت وصول مؤكد. عند انتهاء الاشتراك لا يشرح العميل فاتورة المطعم؛ يعرض «التوصيل غير متاح حاليًا».

## رحلة الموظف والسائق

الموظف يدخل → OTP إن لزم → me → أقسامه فقط. قبول الطلب يحتاج زمن تجهيز واضح؛ الرفض يحتاج سببًا يؤكده المستخدم لأنه يظهر للزبون. عند409 اعرض «تم تحديث الطلب من جهاز آخر» وأعد الجلب.

المطبخ يعرض رقمًا كبيرًا والملاحظات دون صور ثقيلة. الزر يتبع مرحلة واحدة ولا يسمح بالقفز. شاشة المدير تعيّن سائقًا من القائمة الفعلية، والسائق يرى تكليفاته فقط. زر التسليم يفتح تأكيدًا بالمبلغ وطريقة الدفع؛ التحويل غير المؤكد يمنع الإتمام وفق الخادم.

## حالات واجبة لكل شاشة

- Loading: skeleton محدود، لا قائمة فارغة كاذبة.
- Empty: رسالة مرتبطة بالسياق مثل «لا توجد طلبات معيّنة لك»؛ لا إيحاء بصلاحية عرض غيره.
- Error: شرح مختصر + retry قراءة؛ الحفاظ على السلة والمدخلات.
- Offline: آخر تحديث وشارة «بيانات محفوظة»؛ لا نجاح مزيف للقبول أو الدفع.
- Permission denied: تعذر الإجراء وتحديث الدور؛ لا رابط يتجاوز القيد.
- Submitting: قفل الإجراء نفسه + progress، لا ضغط متكرر.
- Success: رقم الطلب والحالة من استجابة الخادم، toast وحده لا يكفي.

«التوصيل قريبًا»، «مشغول حاليًا»، «مغلق الآن»، «تعذّر تحميل المطاعم»، «هذا الصنف غير متوفر»، «تغيّرت بيانات الطلب، حدّثناها لك»، «لم نتمكن من التأكد من إرسال الطلب»، «تأكيد التسليم واستلام المبلغ». زر الرفض أحمر ثانوي، قبول navy أساسي؛ لا زرين متشابهين يؤديان لنتائج متضادة.

## تعريف اكتمال تصميم الشاشة

نسختا RTL/LTR، 360 و390 و768، empty/loading/error/offline/permission، مكونات قابلة لإعادة الاستخدام، semantics وfocus، خريطة endpoint/DTO، حالات الزر، حركة back، keyboard/SafeArea، وتدفقها في prototype. الأيقونات وحدها لا تشرح السعر أو حالة الدفع.
