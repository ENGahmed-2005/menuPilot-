# التحقق وحدود الجاهزية

أُعدت الحزمة في 15 نوفمبر 2026، واستُكملت مراجعة النشر في 16 نوفمبر 2026. المصدر الأساس `c9ba533` مع إصلاح الدليل المرفق. هذه نتائج فعلية للفحوص المحددة أدناه، وليست شهادة قبول شاملة للإنتاج.

## الفحوص التي نجحت

| المجال | النتيجة | حدود الفحص |
|---|---|---|
| Laravel | 54 اختبارًا، 440 assertion | DeliveryDirectoryTest وOutsideOrderTest وAuthorizationTest وAuthSessionsTest، على SQLite داخل الذاكرة |
| تنسيق PHP | Pint ناجح للملفات المعدلة | لا تغيير في اعتماديات المشروع |
| الواجهة | بناء الإنتاج وESLint للملفين المعدلين ناجحان | بقي تحذير حجم الحزمة وتحذير PWA المعروفان |
| دليل المطاعم | عرض 390 و1366 بكسل؛ البحث وفلتر المتاح والروابط والحالات ناجحة | API محاكى لا يكتب إلى الإنتاج؛ لا overflow أو أخطاء JavaScript |
| نموذج الموبايل | 20 شاشة فريدة؛ 105 فحوص للشاشات والحالات | شاشة الدخول مشتركة بين وضعين، لذلك 21 اختيار شاشة × 5 حالات |
| تفاعلات النموذج | البحث، الكمية، السلة، إثبات التحويل، محاكاة الطلب، شرط تأكيد التحصيل للسائق | بيانات توضيحية فقط |
| Collection | 64 طلبًا؛ JSON والمتغيرات والأجسام والمسارات وسكربتات الالتقاط صحيحة | فحص محلي؛ ليس تشغيلًا كاملًا في Postman على خادم حي |
| جرد Laravel | 140 مسارًا من `artisan route:list --json` | مسارات Better Auth منفصلة؛ راجع API.md |

رُوجعت لقطات دليل المطاعم على الهاتف والنموذج التفاعلي بصريًا. الـCollection طابقت عمليات Laravel المطلوبة مع جرد المسارات؛ فُحصت مسارات المصادقة في مصدر خدمة Auth. لم يُحمّل مخطط Postman الرسمي، لذلك لا ندّعي اعتمادًا عبر JSON Schema الرسمي.

## تشغيل الفحوص محليًا

من `backend`، مع إعداد بيئة الاختبار إلى `APP_ENV=testing` و`DB_CONNECTION=sqlite` و`DB_DATABASE=:memory:` و`DB_URL` فارغ:

```sh
php artisan test --compact tests/Feature/DeliveryDirectoryTest.php tests/Feature/OutsideOrderTest.php tests/Feature/AuthorizationTest.php tests/Feature/AuthSessionsTest.php
php vendor/bin/pint --dirty --format agent
```

ومن `frontend`:

```sh
npm run build
npx --no-install eslint src/pages/customer/DeliveryRestaurants.jsx src/i18n/en.js
```

لتجديد جرد المسارات والـCollection من جذر المستودع:

```sh
php backend/artisan route:list --path=api --json > routes.json
python docs/mobile-handoff/build_collection.py routes.json
```

استخدم إخراج UTF-8 لملف الجرد. عند تغيير عقد API أعد فحص المتغيرات والأمثلة والالتقاط، ثم نفّذ سيناريو الدور المطلوب على بيئة اختبار. الـCollection كتالوج سيناريوهات بديلة وليست رحلة واحدة لتشغيل جميع الطلبات بالتتابع.

## ما يحتاج قبولًا تكامليًا قبل إطلاق تطبيق الموبايل

- تسجيل الدخول والكوكيز و2FA والخروج على Android وiOS فعليين، بما يشمل انتهاء الجلسة وسحب الجهاز.
- دورة طلب كاملة بحسابات اختبار لكل دور، على MySQL وبيئة النشر، مع مطعم آخر لاختبار عزل الصلاحيات.
- نتائج انقطاع الاتصال وتكرار الإرسال وتغير السعر أو توفر الصنف أثناء الدفع؛ لا إعادة POST تلقائية عند مهلة مجهولة النتيجة.
- WebSocket واتصال الخلفية والإشعارات على جهاز فعلي؛ وجود الكود ليس إثباتًا لتشغيل خدمة Reverb.
- اختبار التحويل والصورة والرفض والتحصيل وتأكيد التسليم على بيانات اختبار، دون التأثير في طلبات زبائن حقيقية.

لم يُنشأ تطبيق Flutter أو APK بهذه الحزمة، ولم تُرسل طلبات أعمال أو تُغيّر حسابات حقيقية ضمن التحقق. حالة النشر الفعلية تُثبت بمعرّف النسخة المنشورة وفحص HTTP بعد النشر؛ لا تكفي `/up` وحدها.
