# menuPilot — إكمال Sprints 3–6 (فرع `feature/sprints-3-6-completion`)

## أخطاء حرجة تم إصلاحها
| المشكلة | الأثر | الإصلاح |
|---|---|---|
| لا يوجد Route لـ `POST /public/sessions/{id}/orders` | `submitOrder` في الواجهة يرجع 404 (US-10) | تمت إضافة الـ route + alias `POST /sessions/{id}/orders` |
| SSE يكتب `'event: orders\n'` بعلامات تنصيص مفردة | `\n` تُرسل حرفيًا فلا يصل أي حدث لحظي لتتبع الطلب أو شاشة النادل | استخدام علامات تنصيص مزدوجة في البثّين |
| جدول `bill_adjustments` محذوف بينما الكود يكتب فيه | تعديل سعر بند في الفاتورة يسبب خطأ 500 (US-18) | Migration آمن ينشئ الجدول إن لم يوجد |
| إعادة تخصيص صنف ملغي تعيده `active` في نفس الطلب | الصنف يُحسب في فاتورة الطاولتين (US-20) | إنشاء طلب جديد على الجلسة الهدف مع ربط تدقيقي، والأصل يبقى ملغيًا |
| دفع الكاشير يحسب كامل الإجمالي | الطلبات المدفوعة مسبقًا (Pay-first) تُحصّل مرتين | الفاتورة ترجع `total / paid / outstanding` والدفع يسجّل المتبقي فقط |
| دفع الكاشير يُسجّل بحالة `pending` | الدفعة لا تُعتبر مؤكدة | `verified` للنقد/الإلكتروني و`pending_reconciliation` لـ USSD |
| شاشة المطبخ تقرأ `orderNumber/submittedAt/avgPrepTimeMinutes` وحالة بحرف كبير | الشاشة لا تعمل مع الـ backend الحقيقي | استجابة المطبخ تضيف هذه الحقول وتقبل `Preparing` أو `preparing` |

## ميزات جديدة حسب قصص المستخدم
- **US-08** انضمام الزبون الثاني للجلسة النشطة بدل الرفض (`resumed: true`).
- **US-10** رقم طلب تسلسلي لكل مطعم (`order_number`)، مع قفل لمنع التكرار عند التزامن.
- **US-11** ملاحظة اختيارية لطلب النادل، منع الإشعار المكرر، وإنهاء الطلب من الطاقم.
- **US-13** انتقال أمامي فقط Pending → Preparing → Ready → Served مع جدول `order_status_histories`.
- **US-14** وقت تحضير لكل صنف `prep_time_minutes`، متوسط التحضير الفعلي، ومؤشر تأخير، وفرز حسب الوقت المتبقي.
- **US-15** فلترة الطلبات بالتاريخ، إجمالي كل طلب، وتفاصيل طلب معزولة بين المطاعم.
- **US-16** طلب الفاتورة يتطلب طلبًا واحدًا على الأقل.
- **US-17** `POST /sessions/{id}/close` يرفض الإغلاق قبل الدفع، ويحرر الطاولة.
- **US-18** سبب التعديل، ومسار `POST /payments/{id}/reconcile` لتسوية USSD.
- **US-19** الكاشير يستطيع الإلغاء، تسجيل من ألغى ومتى، وخروج الطلب من المطبخ إذا أُلغيت كل أصنافه.

## الواجهة
- صفحة الكاشير `/cashier/billing/:id` مربوطة بالـ API الحقيقي (الوضع التجريبي يبقى عند `VITE_USE_MOCKS=true`).
- شاشة النادل: زر "تمت" يحفظ في الخادم، عرض ملاحظة الزبون، وشارة طلب الفاتورة.
